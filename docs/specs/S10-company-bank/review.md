## Found while fixing, not by the review

**A cached company page kept hidden reviews public.** The plan's acceptance criterion asked for a statically rendered page that revalidates on approval. Static rendering is not available here: the shared header reads the session, which makes every page using it dynamic (the note has been in `AGENTS.md` since S3). The next best thing looked like caching the reads behind a `company:<slug>` tag and dropping that tag on every decision, so I built it.

Driving the real flow in the browser showed it did not work. Publishing a review left the company page unchanged for seconds; hiding one left the hidden text on the public page for about twelve seconds before it cleared on its own. `unstable_cache` and Next 16's `revalidateTag(tag, profile)` are two different caching systems, and the tag never reached the entry.

The layer was removed rather than debugged. The company page is three indexed selects, so it is cheap without a cache, and a cache that can leave a moderator-hidden review public is worse than no cache at all — that is the precise failure the freshness criterion exists to prevent. Both directions were then re-verified in the browser: a pending review is invisible, an approved one appears on the next load, and a hidden one disappears on the next load.

## Deliberate deviations from the plan

- **Reference data is not content.** The plan had `cities` and `job_roles` seeded from a `reference/` folder in the content repo. They are seeded by `pnpm db:reference` in the platform instead. Companies had just left the content repo for being platform data; the lists they group on belong in the same place.
- **The search vector covers prose only.** `cities` and `stack` were meant to be in it, but `array_to_string` is stable rather than immutable, so Postgres refuses it in a generated column. Both are filtered with array operators, which is what the directory needs anyway. `to_char` over a timestamptz has the same problem, which is why the contribution month is computed at read time rather than stored.

## Known gaps, for later specs

- **Readers cannot flag a company review or an interview experience.** `content_flags` and `resolveFlag` already handle the S6 subjects and would extend to these, but no UI offers it, so a bad contribution that gets past an admin has no reader-driven path back to the queue. Worth doing before the bank has real traffic.
- **No company logos yet.** `company_profiles.logo_key` and the R2 driver are in place, but nothing uploads to them; the directory and company pages show names, not marks.
- **Salaries are S10b**, as split by the founder: `salary_points`, the `n ≥ 5` rule, and the salary columns on `company_stats`.

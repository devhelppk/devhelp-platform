# S2 review record

`/code-review high` ran on the S2 diff (14 verifiers; 12 confirmed, 2 plausible, 0 refuted). Every confirmed finding was fixed before landing.

| #   | Finding                                                                                                                                                                  | Fix                                                                                                                                                                                            |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | An empty or missing content directory synced as "zero courses" and archived the whole catalogue.                                                                         | Loader reports a missing `courses/` as an error; `syncContent` refuses an empty tree unless `allowEmpty` is passed. Test: empty and missing dirs are refused and real rows stay live.          |
| 2   | `content:pull` wrote to `CONTENT_DIR`, so it would `rm -rf` an author's sibling checkout.                                                                                | Pull always targets `<root>/.content` (`pulledContentDir`); `CONTENT_DIR` only affects where content is read.                                                                                  |
| 3   | Relative `CONTENT_DIR` resolved against three different bases; empty string was honoured by some tools.                                                                  | One rule everywhere: resolve from the repo root, empty means unset (`@repo/content`, the checker CLI, `content-collections.ts`). Verified from the root with and without `CONTENT_DIR`.        |
| 4   | Renaming or reordering a lesson file changed nothing because the unchanged fast path ignored `position` and `content_path`.                                              | Unchanged now requires equal position and content path (lessons) and content path (courses). Test renames a file and asserts both columns update.                                              |
| 5   | The recovery route depended on the checkout layout and could turn into a wipe on a deploy without `.content/`.                                                           | Route returns 409 when the repo root or content directory is absent, 500 with the message on sync errors; the empty-tree guard closes the wipe path. Documented as local/self-hosted recovery. |
| 6   | gray-matter parsed `updated: 2026-09-01` as a Date while Content Collections kept it a string, so check/sync rejected content the build accepted.                        | The loader parses frontmatter with the `yaml` package, same as Content Collections. Test asserts the value stays a string.                                                                     |
| 7   | A module or lesson without an `NN-` prefix produced `Number.MAX_SAFE_INTEGER` and an integer overflow at sync time.                                                      | Missing prefix is an `order-prefix` error in the loader (so both check and sync refuse). Fixture test added.                                                                                   |
| 8   | Sync skipped the cross-file rules, so unknown refs crashed with raw DB errors and duplicate slugs clobbered rows.                                                        | `syncContent` runs `checkContent` (minus exercise execution) and refuses on any error. Test: a path with an unknown course is refused with the `[ref]` diagnostic.                             |
| 9   | Re-stamping `content_revision_id` on unchanged rows bumped `updated_at` every deploy and made the column mean "last deployed" rather than "commit that changed the row". | Unchanged rows are not written; the deployed commit is the newest `content_revisions` row. Test asserts `updated_at` and revision id are stable across a new sha. Data-model doc updated.      |
| 10  | Empty states and the database README still told users to run `pnpm db:seed` for courses after seeding moved to the content repo.                                         | Copy now says `pnpm content:refresh`; README updated.                                                                                                                                          |

Also fixed from the cut list: dead `content:*` task entries removed from `turbo.json`; the exercise runner defaults to the package's own vitest binary so CI in the content repo needs no `VITEST_BIN`; the checker no longer imports the runner (it is injected), which keeps `child_process` out of the LMS bundle.

Deliberately left: sync issues one query per row (N+1). Content is hundreds of rows, sync runs once per deploy, and every row is inside one transaction; batching can come when a sync takes more than a few seconds. Sync writes jsonb from values already validated by the content schemas rather than re-parsing with the database package's Zod schemas; the shapes are identical today and the sync test covers the mapping.

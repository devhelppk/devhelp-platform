## Browser loop (Chrome, dev servers, Mailpit, MinIO)

Driven by a Playwright script against the installed Chrome with throwaway accounts, plus signed-out checks. Console clean on every page except the known dev-only warning on the 404 page.

Flows: a new learner completes the seeded course (two articles marked done in the UI, the video, exercise, and quiz through the same tRPC calls the pages make) → `certificates` row issued in the completion transaction → "Certificate issued" in the inbox and an email in Mailpit carrying the verify link → `/certificates` shows the card with PDF, copy-link, and Add to LinkedIn → the course page shows the card → PDF download (22 KB, `%PDF-` header) and `pdf_key` set to `certificates/<uuid>/issued.pdf` in MinIO → account page: handle, public switch, bio, GitHub → "Your profile is live" → signed out: `/verify/<uuid>` with `robots: index, follow` lists the lessons and quiz score with the content commit; `/u/<handle>` shows the certificate; unknown uuid → 404 → admin (promoted by SQL) searches and revokes with a reason → admin list shows Revoked → verify page shows the revocation banner, the PDF regenerates (24 KB, stamped), the profile hides the certificate, the learner sees "Certificate revoked" in the inbox → dark theme at 390 px on the verify and certificates pages with no horizontal overflow.

Round 1 found: the profile handle input carried an HTML `pattern` Chrome rejects under the `v` regex flag (the hyphen inside the class), so the form never submitted; after a successful save the profile form remounted (keyed on the handle) and lost its confirmation.
Round 1 fixes: `pattern` removed (the server validates the handle); the form is no longer keyed on the handle.

Round 2 found: the verify page listed the quiz twice (once as a required lesson, once as a quiz score row), and the snapshot recorded the revision that last touched the course row rather than the content commit the platform was serving.
Round 2 fixes: quiz scores merge into the lesson row (`quiz, best score 100%, pass mark 70%`) and only quizzes with no lesson row are listed separately; `certificateSnapshot` reads the newest `content_revisions` row, so the badge shows the deployed commit (`cee5237`).

Round 3: full loop re-run green, including the merged quiz row and the deployed commit; screenshots regenerated. Production build checked separately: `/verify/<uuid>` 200 and the PDF route 200 at 24 KB on `next start`.

Round 4 (after code review, see `review.md`): re-run green after the ten review fixes and the content-revision race fix. The suite was run three times in full to confirm the intermittent certificate insert failure is gone.

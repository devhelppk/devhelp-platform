## Browser loop (Chrome, dev server)

Driven by a Playwright script with throwaway accounts, plus a signed-out pass. Console clean on every page.

Flows: signed out `/badges` lists every badge locked with its rule in words → a new learner marks one lesson done → `first-lesson` awards itself → bell notification → `/badges` shows it earned and the rest locked → the dashboard shows the streak and hides the grid (one active day) → after backdating a day the grid renders 371 cells with two filled → finishing the course awards `course-finisher` from the derived completion event → the public profile carries both badges and the streak → an admin awards `streak-seven` by hand with a reason, and revokes it with another, both stored on the row → dark theme at 390 px on `/badges` and the dashboard with no horizontal overflow.

Round 1 found: the sync reported every badge as updated on every run, because Postgres reorders `jsonb` keys and the comparison used `JSON.stringify`; the streak line used middle dots against the design rules and said "1 active days"; a brand-new learner was shown a full year of empty squares.
Round 1 fixes: badge rules compare by a key-sorted encoding, so a second sync reports four unchanged; the streak reads as a sentence with correct plurals; the grid appears only once a learner has been active on more than one day.

Round 2: full loop re-run green, asserting both the hidden and shown grid states; screenshots regenerated.

Round 3 (after code review, see `review.md`): re-run green after the eight review fixes, including the two that changed behaviour (path badges now award, and one event reports every badge it earned). The full suite was run three times to check the flaky concurrency failure noted in the review; it did not recur.

## Known limitations

- `steady-week` (five lessons in seven days) was not earned in the loop: the seeded course has four completable lessons. The rule itself is covered by a three-lesson badge in the learning tests.
- `first_project_accepted` cannot be earned until project lessons run automated checks; `content:check` warns rather than failing, as the founder asked.
- No backfill (founder, mid-implementation: no users yet), so a badge published later applies from that point on. The backlog carries the script for when there are learners.
- Test accounts, awards, and activity rows from the loop remain in the local database.

# S8 review record

`/code-review high` ran on the S8 diff and reported eight findings, two of them high. All were verified by hand and fixed.

| #   | Finding                                                                                                                                                                                                                                                                                                    | Fix                                                                                                                                                                                                                                                  |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **`path_completed` badges could never be earned.** Badges were evaluated at the top of `applyEvent`, before the `course_completed` case marked the enrolment complete, so the rule asking "is every course in this path done?" always saw the last one still active. Nothing else triggers that rule.      | Badges are evaluated after the read models move. Test: a learner finishing the only course in a path earns the path badge.                                                                                                                           |
| 2   | **Badge notifications were lost when one event awarded at two levels.** `applyEvent` recurses for derived events and the callback assigned rather than accumulated, so a lesson that both earned a window badge and completed the course reported only the second; the first row existed with nobody told. | The callback accumulates. Test: one event reports and notifies both badges.                                                                                                                                                                          |
| 3   | **`rebuildLearner` inflated activity for implicit enrolments.** The live path creates the enrolment without routing the derived `course_enrolled` through `applyEvent`, but a replay feeds every stored event through it, so each rebuild added one to that day's count.                                   | A derived auto-enrol is not counted: live it never reaches the counter, and its day is already the triggering event's. Test: a learner who never enrolled explicitly rebuilds to identical rows.                                                     |
| 4   | **The whole lucide icon set reached the browser on `/admin/badges`.** `BadgeIcon` looks icons up dynamically, so nothing tree-shakes, and it was imported by a client component: roughly a megabyte of JS on a route the budget script does not measure.                                                   | `BadgeIcon` is documented and used as server-only; the admin list shows the badge name without the icon. The badge grid, which does render icons, is a server component.                                                                             |
| 5   | **Badge evaluation ran on every video heartbeat.** `lesson_progressed` ticks are the hottest event in the system, and a `streak_days` badge made each one read the learner's whole activity history inside the write transaction.                                                                          | Heartbeats record activity (one upsert) and skip evaluation: they satisfy nothing.                                                                                                                                                                   |
| 6   | The admin form chose award or revoke from React state set in `onClick`, so a keyboard submit ran whichever was used last. On a button that revokes.                                                                                                                                                        | The action comes from the submitter, with `name` and `value` on each button.                                                                                                                                                                         |
| 7   | The dashboard said "N days active in the last year" while the query counted all time.                                                                                                                                                                                                                      | The streak query is bounded to a year, matching the grid and the copy.                                                                                                                                                                               |
| 8   | A revoked badge could never be re-earned automatically, which was undocumented.                                                                                                                                                                                                                            | Made explicit in the code: revocation is final for the rules (they are monotonic, so re-evaluating would undo the moderator on the learner's next click), and an admin re-awards through `badges.award`, which restores the row with the new reason. |

Found while fixing, not resolved

- **One flaky failure in the concurrency test.** `emits exactly one course_completed when the last two lessons complete concurrently` failed once on the certificate insert during a full parallel run, then passed in isolation and in three consecutive full runs. S8 adds an activity upsert and a badge insert to those transactions, so a lock-ordering interaction is plausible, but the enrolment `FOR UPDATE` serialises the path and I could not characterise or reproduce it. Recorded here rather than papered over with a speculative fix; worth watching if it recurs.

Deliberate leftovers

- `steady-week` (five lessons in seven days) is unearnable on the seeded content, which has four completable lessons. The rule is covered by a three-lesson badge in the tests.
- No backfill (founder decision mid-implementation: no users), so a badge published later applies from that point on.

# S6 review record

`/code-review high` ran on the S6 diff; its verification pass confirmed all twelve findings it raised (ten reported under its cap, two conventions findings noted). Every one was fixed before landing.

| #   | Finding                                                                                                                                                                                                               | Fix                                                                                                                                                                                                             |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `comments.edit` re-rendered the body but never re-ran the hold check or refreshed the queue snapshot, so a new account could post plain text and edit in a link, and a held comment could change under the moderator. | Edit re-runs `holdReason`; a link from a new account holds the comment (item created or re-opened, snapshot refreshed, `edit`/`submit` action logged); a pending snapshot is updated on every edit. Test added. |
| 2   | `reviews.submit` forced `status` back to `visible` on edit, so an author could republish a moderator-hidden review and the flag path could not hide it again.                                                         | Edits never touch `status`; only a moderation decision does. Test: editing a hidden review leaves it hidden.                                                                                                    |
| 3   | `applySubjectStatus` overwrote a deleted comment's status (approve resurrected an empty body; hide relabelled it as moderator-removed), and `comments.remove` left its pending item open.                             | Deleted comments are never changed by a decision; `remove` rejects a pending item with "author deleted the comment" and logs it. Test added.                                                                    |
| 4   | Comment and review submitters were notified with the company-review-request wording ("Your review request was accepted") and no link to the thread.                                                                   | `decidedNotification` words and links the notification per subject type ("Your comment is published", link to the thread or course).                                                                            |
| 5   | Edit opened a blank textarea (`setDraft(c.bodyHtml ? "" : "")`) and the list never returned the Markdown source.                                                                                                      | `comments.list` returns `body` for the caller's own visible comments (blank otherwise); Edit seeds the draft from it. Test asserts the source is only sent to its author.                                       |
| 6   | A held-then-approved comment never announced itself: no `comment_reply` to the question author, no `lesson_question` to watchers.                                                                                     | `announceComment()` runs after the commit that makes a comment visible, on create and on approval. Test: a watcher is notified when a held question is approved.                                                |
| 7   | Pagination used a `createdAt` cursor for the vote-ordered "top" sort, so page two repeated and skipped threads.                                                                                                       | Keyset cursor `{ voteCount, createdAt }` for both sorts.                                                                                                                                                        |
| 8   | `comments.remove` decided `wasVisible` from an unlocked pre-transaction read and decremented `replyCount`, racing moderation's recount.                                                                               | `remove` locks the row inside the transaction and `replyCount` is always recounted from source (`recountReplies`), also on create, edit, and moderation.                                                        |
| 9   | The course page passed `verified` from the cookie-cached session, so the review form and the discussion composer could disagree for five minutes after a verify link.                                                 | `reviews.mine` returns `verified` from the users table; the form reads it there.                                                                                                                                |
| 10  | `flag` inserted the synthetic "approved" item before the transaction that ran the rate limit, leaving orphan items on rate-limited or failed flags.                                                                   | Snapshot and insert moved inside the transaction after `rateLimit`.                                                                                                                                             |
| 11  | The moderation item page used raw `<a href="/courses/…">` for internal links.                                                                                                                                         | `next/link` with typed routes.                                                                                                                                                                                  |
| 12  | Two docs files were not Prettier-formatted, which would fail CI's `format:check`.                                                                                                                                     | Formatted; the full pipeline including `format:check` passes.                                                                                                                                                   |

Deliberate leftovers

- `reviews.remove` deletes the row; a later `submit` creates a new review id, so the earlier flag history stays on the old item rather than following the author. The item and its actions are kept, which is what an audit needs; a per-author view of moderation history is S11 territory.
- Comment code blocks are styled, not syntax-highlighted (plan decision 4).
- The `anchor` column is written by the API but the UI does not yet offer "comment on this section".

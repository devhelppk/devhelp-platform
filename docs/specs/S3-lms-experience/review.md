# S3 review record

`/code-review high` ran on the S3 diff (18 verifiers; 14 confirmed, 4 refuted). Every confirmed finding was fixed before landing.

| #   | Finding                                                                                                                                                                                                   | Fix                                                                                                                                                                                                                                  |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | Video progress-tick nonce was a per-mount counter from 0, so a second viewing session collided with the first session's idempotency keys and its ticks were dropped.                                      | Nonce is `<mount-unique id>-<tick>`.                                                                                                                                                                                                 |
| 2   | Lesson start/complete keys had no enrolment generation, so after drop + re-enrol a lesson could never be re-completed and the course stuck at 0%.                                                         | Keys carry `:g<n>` where n = count of `course_enrolled` events for the learner and course. Test: drop → enrol → complete → `courseCompleted` true.                                                                                   |
| 3   | Dashboard treated every `myEnrollments` failure as "signed out", rendering the landing page to signed-in users during outages with nothing logged.                                                        | Only `UNAUTHORIZED` maps to the landing; other errors rethrow. Added `app/error.tsx` (branded boundary with digest and retry).                                                                                                       |
| 4   | `NEXT_PUBLIC_*` URLs defaulted to localhost, so a production deploy missing them shipped localhost links and localhost-only auth trusted origins; the marketing build already contained `localhost:3001`. | Defaults apply only outside production (required in production). Both apps inline the validated values through `next.config.ts` `env`, so the build fails rather than shipping a default. Root `.env` carries them for local builds. |
| 5   | YouTube API `onReady` callback was never cancelled; under StrictMode or fast navigation a dead closure created the visible player and its 15 s interval leaked after unmount.                             | `active` flag flipped in cleanup; `init` returns early when inactive.                                                                                                                                                                |
| 6   | "Mark as done" on the last lesson neither refreshed the server-rendered page nor updated local state, so the button stayed enabled and the tick/badge never appeared.                                     | Local `done` state plus `router.refresh()` on success.                                                                                                                                                                               |
| 7   | Path chips counted unfiltered `pathCourses` while the path page filtered unpublished/archived courses, so counts disagreed.                                                                               | `listPaths` applies the same visibility filter and returns `courses`; chips with zero visible courses are hidden. Test compares list vs detail.                                                                                      |
| 8   | `myEnrollments` returned dropped enrolments, so a learner with only dropped courses saw "Pick up where you left off" above an empty page.                                                                 | Dropped rows are filtered out server-side. Test asserts an empty list after drop.                                                                                                                                                    |
| 9   | `revalidate = 300` on catalogue/path pages was dead: `searchParams` and the session-reading header make them dynamic; the prerender manifest confirmed it.                                                | Pages declare `force-dynamic` honestly; plan and `AGENTS.md` updated.                                                                                                                                                                |
| 10  | Importing `@repo/env` from `packages/content` and `packages/database` made `content:pull` and `db:generate` demand auth secrets they never use.                                                           | `@repo/env/database` slice (DATABASE_URL, pool) for the database package; `packages/content` reads `process.env.CONTENT_DIR` directly; `SKIP_ENV_VALIDATION` documented. Test: the slice validates with only `DATABASE_URL`.         |

Also fixed from the cut list: dead `lib/trpc/server.tsx` and unused `@next/third-parties` / `server-only` dependencies removed; `as never` route casts replaced with `as Route` so `typedRoutes` actually checks them.

Refuted by the verifiers (no change): lesson-count mismatch (sync archives lessons with their module); deferred toaster losing early toasts (sonner replays queued toasts); a backslash bypass of `safeCallback` (Better Auth's origin check rejects it first); content-directory resolution from cwd (the loader joins onto cwd, so the code is right).

Deliberately left: three `getSession` calls per request on lesson pages (header, page, tRPC context; each is a cookie read plus one cached query, and consolidating means threading the session through the API context, which S5 will do when email verification lands); `courseProgress` awaits sequentially (three small queries; batching adds complexity for no measurable gain at this scale).
